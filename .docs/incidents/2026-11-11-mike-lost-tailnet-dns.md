# 2026-11-11: mike stopped resolving tailnet names, and a deploy could not pull its image

| | |
|---|---|
| Window | 2026-11-11 03:25 to 06:53 UTC (04:25 to 07:53 Prague) |
| Affected | mike: every MagicDNS name, the container registry on the NAS included |
| Detected by | a person, from a failed deploy, about 3 h after it started; nothing alerted |
| Sources | tailscaled and dhcpcd journals on mike and gus, the deploy job log, `ls -l /etc/resolv.conf` on every box |
| Status | fixed on every box by [#587](https://github.com/landsman/homelab/pull/587), not merged yet |

## 1. Summary

dhcpcd and tailscaled both write `/etc/resolv.conf` on every pollos box, and have been taking it
from each other about 35 times an hour. tailscaled always took it back, until 03:24 UTC on mike,
when it started rewriting the file, never confirmed it, and stopped watching it. dhcpcd's next
write at 03:25 stayed, and mike asked the router for names only the tailnet knows. Confirmed from
the journals; why tailscaled stopped watching is inferred (see limits).

Impact: one deploy failed, it could not resolve the registry. No data lost. It needed a person:
nothing would have put the file back on its own.

## 2. Impact

| Service | Effect |
|---------|--------|
| deploys to mike | failed at the image pull, `no such host`; one run known, at 06:19 UTC |
| anything else on mike reaching a box or the NAS by its tailnet name | failed for 3 h 28 min; nothing else known to have tried |
| gus, walter, jesse, saul | not affected: their tailscaled kept winning the same fight |

## 4. Cause and evidence

Two programs own one file, and the box only works while tailscaled wins. Confirmed: the fight and
the moment mike's tailscaled stopped answering it are both in the journal.

- dhcpcd signs what it writes (`# Generated by dhcpcd from eno1.dhcp, eno1.dhcp6`), and that is
  the file mike had from 03:25 to 06:53.
- Every tailscaled entry before 03:24:14 is a set of four: `trampled`, `Set`, `again matches
  expected content`, `ok`. The one at 03:24:14 stops after `Set` and `OScfg`, and no `trampled`
  follows for three and a half hours, while the route changes that used to trigger one go on.
- tailscaled itself was alive: it kept logging endpoint changes and peer contacts throughout.
- The route changes are an IPv6 prefix announced by some other device on the LAN, appearing and
  disappearing every minute or two. Each one makes dhcpcd rerun its hooks.
- Recurrence: the fight is on every box today (gus: 35 in the last hour); mike's journal shows it
  for the three days checked. Only mike lost it.

What it was not:

- the registry: the image job pushed to it in the same run, and the other boxes resolved it;
- tailscale down on mike: `tailscale status` showed the node up, and its log kept going;
- a change to the tailnet's DNS settings: every `dns: Set` on mike and gus logs the same config.

Limits of the data:

- Why tailscaled stopped after 03:24:14 is not in its log. A write it could not confirm while
  dhcpcd wrote again fits, but is inferred.
- What wrote `resolv.conf` on the other four boxes at 06:36:55 is not known; mike's tailscaled
  logged nothing then, which fits it being stuck.
- The tailscaled journal on mike has no `trampled` lines from 2026-11-10 17:00 to 2026-11-11
  03:00 UTC; the route was presumably quiet, not read further.

## 5. Current state

At 2026-11-11 07:05 UTC: all five boxes have `nohook resolv.conf` in `/etc/dhcpcd.conf`, their
`resolv.conf` is tailscaled's, and each still runs the one dhcpcd it had (same pid). On each, a
forced lease renewal left the file alone. On mike, a real route change at 06:5x UTC passed with no
`trampled` line, while gus logged five in the ten minutes before it got the fix.

Learned: two programs writing one file is a bug even while one always wins, because then the
winner's watcher is the only thing keeping the box up, and it fails silently.

## Appendix

On a box, as root:

```sh
# who wrote it last, and when
head -1 /etc/resolv.conf; ls -l /etc/resolv.conf
# the fight, per hour
journalctl -u tailscaled --since -3d -o short-iso | grep 'was trampled' | cut -c1-13 | uniq -c
# what tailscaled did around a given moment
journalctl -u tailscaled --since '2026-11-11 04:15' --until '2026-11-11 04:35' -o short-iso \
  | grep -E 'trampl|dns: |resolv-conf'
```
